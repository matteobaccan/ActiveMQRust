# Soak test: ActiveMQRust vs ActiveMQ 5.18.7 and 6.3.2 (2026-10-05)

Generated with `scripts\soak-compare.ps1` (Java bench client, scenario `soak`). Results apply to this machine only.

- Machine: Intel Xeon W-2123 @ 3.60 GHz (4 cores, 8 logical processors), 31.7 GB RAM, Windows 11 Pro for Workstations (build 26200)
- JDK: OpenJDK 21.0.12.1
- ActiveMQRust release build of commit `fa52465` (the 0.2.0 code, built before the version number was raised), default configuration (no configuration file)
- ActiveMQ 5.18.7 and 6.3.2 with the tuned in-RAM configuration `scripts/activemq-bench/activemq-tuned.xml` (no persistence, VM cursor, no producer flow control, JVM `-Xmx4g`)
- One shared queue, NON_PERSISTENT, AUTO_ACKNOWLEDGE, async send, prefetch 1000, XML TextMessages
- Each producer sends at a steady pace, spread over the send interval; all producers and consumers run at the same time
- Checks on every message: per-producer `seq` increasing at every consumer, no message lost, none delivered twice, body length
- One run per broker; the brokers ran one after the other on the same machine. Latency is end to end (send to receive, same JVM)

## Reading the results

- All three brokers delivered every message exactly once and in order per producer in both runs.
- At this steady load ActiveMQRust used about 17 times less Working Set and about 40 times less Private Bytes than ActiveMQ, and between half and a third of the CPU per message. It started about 25 times faster.
- Median latency is similar for all brokers (it is dominated by the client and the network stack); ActiveMQRust has the lowest p99 and maximum.
- These are single runs at a fixed, moderate rate: they measure resource use and correctness under a steady load, not maximum throughput. The full comparison (measurements (a)–(f), 3 runs each) is still to be run.
