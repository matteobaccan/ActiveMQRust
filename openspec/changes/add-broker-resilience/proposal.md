## Why

Load tests never crashed ActiveMQRust, but nothing has tried to break it on purpose: malformed or hostile OpenWire frames are not fuzzed, the release build aborts the whole process on a panic, `max_memory_mb` is unlimited by default so a backlog can grow until the operating system runs out of memory, and the Windows service is not restarted after a failure. Target: version 0.4.0.

## What Changes

- Fuzzing of the OpenWire frame decoder and the selector parser (`cargo-fuzz`), with any crash turned into a regression test.
- A failure on one connection (malformed frame, unexpected state) closes that connection only, never the broker; panics on the message path are removed or contained.
- A safe default memory limit (a share of physical RAM) instead of unlimited, with the current behaviour at the limit (synchronous sends refused, asynchronous sends discarded and counted, acceptance again below 90%).
- Stress tests: thousands of connections opening and closing, very slow consumers with large prefetch, a backlog driven to the memory limit.
- `service install` configures the Windows service recovery actions (restart after 5 s, 30 s, then 2 min; reset after 24 h; non-crash failures count), shown by `service status`; the broker logs when it starts after an unexpected stop.
- macOS: a launchd property list with `KeepAlive` (template in the README, or generated by `service install` on macOS).

## Capabilities

### New Capabilities

- `broker-resilience`: crash isolation, fuzzing, safe memory default, stress tests, automatic restart.

### Modified Capabilities

None yet; the memory default will modify `memory-management` when designed.

## Impact

- `fuzz/` targets, `src/connection.rs`, `src/openwire/`, `src/config.rs` (memory default), `src/service.rs`, README.
